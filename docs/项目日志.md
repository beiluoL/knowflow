## 2026-07-31 证书获得庆祝弹窗 + 章节完成按钮布局收敛

### 功能概述
学习路径完成时不再「无感获得证书」：完成最后一章（路径达成 100%）后弹出带彩带动效的全屏「恭喜获得证书」庆祝弹窗，可跳转证书页查看；同时将「标记本章已完成」按钮从正文底部的大号醒目块移入底部固定操作栏，与「下一章」并排、适度强调。

### 前端（Vue 3 + TS）
- 新增全局庆祝子系统：
  - `utils/celebrate.ts`：仿照 `toast.ts` 的 reactive 全局状态 + 函数式 API，提供 `celebrateCertificate(cert)` / `dismissCelebration(id)`
  - `components/ui/Celebration.vue`：全屏庆祝弹窗宿主（金色奖章 + 证书信息 + 彩带飘落 CSS 动效 + 「查看证书」跳 `/certificate/:id` + 「稍后查看」），挂载到 `App.vue`
- `ChapterLearn.vue`：
  - 移除正文底部 `.chapter-complete-bar` 大号醒目块，完成操作移入底部固定操作栏「下一章」旁：未完成未锁定→「标记本章已完成」按钮（品牌绿描边 + 细阴影，适度强调）；已完成→「本章已完成」徽标；已锁定→解锁提示
  - 完成**最后一章**后调 `checkPathCertificate()`：查 `learningApi.certificates()` 按 pathId 找证书（幂等同路径单证书），命中则 `celebrateCertificate` 触发庆祝，避免无感获得证书

### 设计决策
- 庆祝特效聚焦「获得证书」这一明确场景（用户确认）：成就解锁、等级提升、称号进阶保持现有 notify 轻提示，不做每次章节完成后的拉取比对
- 彩带动效用纯 CSS `@keyframes` 实现，不引入外部特效库；色值取自 `kb-*` 变量 + 有限庆祝色板

### 同步文档

- `docs/项目日志.md`：本条目

### 功能概述
新增 C 端「编程挑战」菜单：挑战赛道内含 10 道关卡，逐关解锁；浏览器端执行测试用例判题，后端判定通关并计算星级、积分与解锁；提供积分排行榜与个人战绩统计。

### 数据库（schema.sql / data.sql，H2 内存库随启动初始化）
- `code_challenge` 挑战赛道表（标题/语言/难度/图标/主题色/关卡数/总积分/状态）
- `code_challenge_level` 关卡表（level_no 序号、题目描述、示例、提示、代码模板、测试用例 JSON、积分）
- `code_challenge_record` 用户赛道进度表（通关数/当前关卡/累计积分/星星/是否全通）
- `code_challenge_level_record` 用户关卡记录表（是否通关/星级/尝试次数/所得积分/最近代码）
- 种子数据：1 条「JavaScript 十题闯关」赛道 + 10 道关卡（两数之和 → 经典算法，循序渐进）

### 后端（Spring Boot 3 + MyBatis-Plus）
- 实体：`CodeChallenge` / `CodeChallengeLevel` / `CodeChallengeRecord` / `CodeChallengeLevelRecord`
- Mapper：对应 4 个 BaseMapper
- DTO/VO：`ChallengeSubmitDTO`；`ChallengeVO` / `ChallengeDetailVO` / `ChallengeLevelVO` / `ChallengeSubmitResultVO` / `ChallengeRankVO` / `ChallengeStatsVO`
- 服务：`CodeChallengeService` / `CodeChallengeServiceImpl`
  - 判分模式与代码题库一致：前端跑用例上报 total/passCount，后端判定通关
  - 星级：1 次通过 3 星，2-3 次 2 星，≥4 次 1 星（仅首通计星计分）
  - 积分：3 星满分 / 2 星 80% / 1 星 60%，首通积分同步累加到用户 `exp`
  - 解锁：提交时校验上一关已通关；详情接口按顺序计算 locked
  - 排行榜：按用户聚合积分（同分比星星），支持单赛道榜与总榜
- 控制器：`CodeChallengeController`（`/api/challenges`）
  - GET `/api/challenges`、`/{id}`、`/leaderboard` 匿名可读（SecurityConfig 放行，登录后附带个人进度）
  - POST `/{challengeId}/levels/{levelId}/submit`、GET `/my/stats` 需登录

### 前端（Vue 3 + TS + Pinia）
- `api/challenge.ts` + `api/types.ts` 新增 6 个 Challenge* 类型
- 路由：`/challenge`（列表，匿名可看）、`/challenge/:id`（闯关，需登录）
- `CTopNav.vue`：桌面端「学习工具」下拉与移动端菜单新增「编程挑战」（rocket 图标）
- `Challenge.vue`：我的战绩卡 + 赛道卡片（进度条/星星/积分/参与人数）+ 积分排行榜 + 玩法说明
- `ChallengePlay.vue`：关卡地图（锁定/通关/当前态 + 星级展示）+ 题目面板（示例/提示折叠）+ 代码编辑器（Tab 缩进/重置模板/恢复上次代码）+ 浏览器端判题 + 通关弹窗（星级/积分/下一关）

## 2026-07-30 修复前端生产构建（npm run build 闭环）

- 现象：`npm run build`（`vue-tsc -b && vite build`）此前失败，无法产出 `dist/`，阻塞部署。
- 根因两类：
  1. `vue-tsc -b` 严格类型检查约 60+ 处 TS 错误（未使用变量/参数、类型不匹配、可选属性访问、`<script setup>` 误删被模板使用函数等），分布在约 30 个文件（含 B/C 引入的 `KnowledgeGraph`/`LearningReport`/`SmartWriting` 与历史遗留的 `DocEdit`/`Favorites`/`FlashCards`/`KBTitle`/`KnowledgeHome`/`NoteEdit`/`PathDetail`/`Profile`/`SearchResult`/`TaskCenter` 等）。
  2. Vite 8 的 lightningcss 在 minify 阶段报非法 CSS 选择器 `.[-:T]{ -: T; }`：`MyFlashcards.vue` 中日期格式化正则 `/[-:T]/g` 被 Tailwind 按原始文本扫描，误当作「任意属性类」`[-:T]` 生成无效 CSS。
- 修复：逐文件修复 TS 错误；将正则拆为 `.replace(/-/g, '').replace(/:/g, '').replace(/T/g, '')` 以消除连续 `[-:T]` 子串。
- 校验：`npm run build` 退出码 0，`dist/` 正常产出（仅剩 chunk 体积 >500 kB 的非致命警告，可后续用动态 `import()` 做代码分割优化）。
