# Web 端功能补齐开发计划（以桌面端为基线）

> **版本**：v1.0 ｜ **日期**：2026-08-16
> **配套文档**：`docs/桌面端与Web端功能差异对比.md`
> **目标**：将 Web 端（`frontend/` + `backend/`）功能补齐至与桌面端（`desktopApp/`）**对等**的水平，保留 Web 既有平台生态（社区/编程/路径/游戏化）。

---

## 0. 目标与原则

### 0.1 目标
对照《功能差异对比》识别的差距，分 6 个阶段、约 **20 个相对工作周**，把 Web 端在「工作台算法深度」「生产力闭环模块」「个人效率自动化」三方面补齐到桌面端基线，并实现 **Web ↔ 桌面 双向迁移**。

### 0.2 原则（硬约束）
1. **只补不删**：所有 Web 端独有能力（社区/编程 Agent/学习路径/游戏化/管理后台/OAuth）一律保留，不得为对齐而降级。
2. **沿用既有规范**：前端遵循 `frontend-code-standard` + `ui-design-system`（主色 `#3B6FE0`、卡片 `#FFFFFF`、左侧栏+顶栏布局、Lucide 图标）；后端遵循《阿里巴巴 Java 开发手册》+ 逻辑外键 + 表必备 `id/create_time/update_time` + 逻辑删除。
3. **本地优先验证**：每个阶段完成后必须本地跑通（`mvn ... spring-boot:run` + `npm run dev`）再交付，不只用 `npm run build` 验证。
4. **桌面端冻结**：依据项目约定，桌面端已进入冻结维护态，本计划**只改 Web 端**；逆向迁移导入在 Web 端实现（桌面端导出格式已稳定）。
5. **文档同步**：每个阶段涉及的端点数/路由/表结构变更，同步更新 `README` 与相应技术方案文档。

## 1. 阶段总览

| 阶段 | 名称 | 关键交付 | 相对工期 |
|---|---|---|---|
| **P0** | 数据模型与基建对齐 | wb_* 字段对齐、AI 流式确认、迁移兼容层 | W1–W2 |

## 2. 分阶段任务详述

### 阶段 P0 —— 数据模型与基建对齐（W1–W2）

**目标**：为后续增强扫清数据层与基础设施障碍。

| 任务 | 前端 | 后端 | 验收标准 |
|---|---|---|---|
| 0.1 对齐 `wb_*` 表字段（去重/剪藏/语音/双向迁移所需列） | — | `WorkbenchServiceImpl` + `schema.sql` 补列（按桌面 `wb_capture/wb_note/wb_review_card` 对齐，逻辑外键 + 索引） | 两端字段语义一致，迁移可导 |
| 0.2 确认并落地 AI 流式 SSE 前端消费 | `Chat.vue` 接 `ai/SseClient` 流式 | `ChatController./send` 校验 SSE 输出 | 前端可见逐 token 流式 |
| 0.3 迁移格式兼容层（逆向：Web 消费桌面整库） | 导入向导页 | `WorkbenchController` 新增 `POST /workbench/import`（解析桌面导出 JSON，事务内重映射 id） | 桌面导出文件可在 Web 端导入 |

**里程碑 M0**：Web 端可导入桌面整库；AI 对话确认流式。

---

### 阶段 P1 —— 高感知低成本增强（W3–W4）

**目标**：最低成本提升首屏与操作效率感知。

| 任务 | 前端 | 后端 | 验收标准 |
|---|---|---|---|
| 1.1 ⌘K 命令面板 | 新增 `CommandPalette.vue`（命令列表：新建笔记/开始番茄钟/跳转模块/模糊搜索），`CTopNav` 唤起 | 复用 `UserSearchController` + 新增命令索引接口 | ⌘K/Ctrl+K 唤起，可执行动作 + 模糊跳转 |
| 1.2 新手引导向导 | 新增 `Onboarding.vue`（分步 tour + 首登标记，写 `user_prefs`） | `UserController` 补 `onboarded` 标记读写 | 首次登录走引导，可跳过/完成态持久化 |

**里程碑 M1**：⌘K 命令面板可用；新用户首次登录引导完成。

---

### 阶段 P2 —— 工作台核心算法增强（W5–W8）

**目标**：补齐学习效率核心的算法与 AI 深度（差异对比 2.1）。

| 任务 | 前端 | 后端 | 验收标准 |
|---|---|---|---|
| 2.1 双 SRS 系统 | 复习页支持跨源队列（note + loci）、算法切换 | `wb_review_card` 扩 `source_type`；新增跨源复习调度（SM-2 + 可选 FSRS 类）；热力图/遗忘曲线接口 | 笔记与记忆桩进入统一复习队列，可切换算法 |
| 2.2 AI 生成记忆桩 | `MemoryPalaceEdit` 接 AI 生成按钮 | 新增 `palace/loci/generate` 端点（LLM 生成桩位 + 内容挂载） | 一键生成桩位并落库 |
| 2.3 语义化主动回忆评分 | `WorkbenchRecall` 接语义评分结果 | 新增 `recall/score` 端点（LLM 语义相似度 + 进步率 + 建议） | 回忆评分基于语义，非字符串比对 |
| 2.4 捕获增强 | 捕获页接去重/剪藏/语音上传/多目标沉淀 | `inbox`-类端点：去重检测、网页剪藏、语音/附件上传、转笔记/宫殿/故事 | 捕获全链路可用 |
| 2.5 笔记增强 | 双链反链渲染、标签云、单篇导出按钮 | 双链解析接口、标签聚合接口 | 笔记可双链、可单篇导出 |
| 2.6 双向迁移收尾 | 导入进度/冲突提示 UI | 0.3 导入接口完善（冲突策略、进度） | 桌面↔Web 双向迁移闭环 |

**里程碑 M2**：复习支持双算法跨源；记忆桩可 AI 生成；主动回忆语义评分；捕获/笔记增强上线；双向迁移完成。

---

### 阶段 P3 —— 生产力闭环模块（W9–W14）

**目标**：补齐 7 项缺失中的 5 项生产力模块（差异对比 2.2）。

| 任务 | 前端 | 后端 | 验收标准 |
|---|---|---|---|
| 3.1 思维导图编辑器 | 中心节点放射编辑器（增删/折叠/JSON 存取） | `MindMap` CRUD 接口（JSON 存储） | 可创建/编辑/导出思维导图 |
| 3.2 绘图 / 流程图编辑器 | 画布（节点拖拽/连线/撤销重做/导出）；可基于 Mermaid 增强或 X6 式 | 图表 JSON 存取接口 + 版本历史 | 可绘制并导出流程图 |
| 3.3 四象限 | 2×2 拖拽看板 | `QuadrantTask` CRUD（urgent/important 维度） | 任务可拖入四象限 |
| 3.4 日历事件模块 | 月/周/日三视图、事件 CRUD、与任务/复习联动 | `CalendarEvent` 接口（范围查询） | 日历可增删事件并与复习/任务关联 |
| 3.5 Things3 式任务清单 | 智能列表（inbox/today/upcoming/someday/logbook）、子任务、清单/领域/项目层级 | `Task`/`TaskList` 表（`parent_id` 层级 + 智能列表查询） | 任务支持子任务与智能列表 |

**里程碑 M3**：思维导图、绘图、四象限、日历、层级任务五大模块全部可用，个人效率工作台闭环成形。

### 阶段 P4 —— 个人效率与自动化（W15–W18）

**目标**：补齐剩余缺失项与自动化能力。

| 任务 | 前端 | 后端 | 验收标准 |
|---|---|---|---|
| 4.1 整库备份 | 备份/恢复/列表 UI | `POST /backup`、`GET /backup/schedule`（整库快照 zip + 可恢复 + 定时） | 可一键整库备份并恢复 |
| 4.2 每日学习日报 | `DailyReport.vue` | `insight/daily-report`（聚合当日行为 + AI 文案 + 薄弱点→闪卡） | 每日生成 AI 学习日报 |

| 5.3 端到端联调与回归 | 全模块冒烟 | 全接口回归 | `npm run build` 通过 + 本地跑通 |
| 5.4 文档同步 | — | 更新 `README`、端点/路由清单、相关技术方案 | 文档与代码一致 |

**里程碑 M5（终）**：Web 端功能与桌面端基线**完全对等**，横切能力（同步/快捷键/通知）打通，文档更新完毕。

## 4. 风险与依赖

| 风险 / 依赖 | 影响 | 缓解措施 |
|---|---|---|
| **AI 能力依赖外部 Key**：语义评分/AI 记忆桩/日报需 `AI_API_KEY` | 无 Key 时功能降级 | 沿用既有 mock 降级策略（桌面端已验证） |
| **STT/TTS 资源**：模拟面试需 Whisper/PIPER 类能力 | Web 端无本地推理，需云端或第三方 | 优先接云端 STT/TTS，或首版仅文本面试 |
| **表结构变更**：双 SRS/任务层级/日历需加列或新表 | 迁移与回归成本 | P0 统一评审 schema，逻辑外键 + 索引，H2 重启回种子 |
| **前端规范一致性**：新增 5+ 大模块易破坏 UI 基线 | 视觉/交互不一致 | 每模块走 `ui-design-system` 验收清单；复用现有布局组件 |
| **与桌面端导出格式耦合**：逆向迁移依赖桌面导出契约 | 格式变更会断 | P0 冻结桌面导出 schema，文档化字段契约 |
| **工期漂移**：P3 模块量大（绘图/日历/任务） | 总工期延长 | P3 内部并行；绘图可先用 Mermaid 增强过渡 |
