## 1. 概述与产品定位

消息功能为 `knowflow` 知识库平台提供即时通讯能力，包含两种会话形态：

| 形态 | 业务载体 | 说明 |
|---|---|---|
| **私聊（单聊）** | `PrivateConversation` 会话 | 任意两个用户之间的 1:1 点对点聊天 |
| **群聊** | `StudyGroup`（学习小组） | 基于「学习小组」的群组聊天，成员关系由小组决定 |

核心能力：文本 / 图片 / 文件 / 代码片段（CODE）四类消息；**已读回执**；**消息撤回**；基于 WebSocket 的实时推送（新消息、已读回执、撤回、输入中状态、会话未读更新）。

> **注意**：平台另有一套独立的「AI 对话」模块（`ChatController` / `ChatService` / `api/chat.ts`），与本消息功能**完全无关**，请勿混淆。

## 2. 技术架构总览

```
┌─────────────────────────────┐         ┌──────────────────────────────────┐
│  Frontend (Vue 3 + TS)      │         │  Backend (Spring Boot 3)         │
│                             │         │                                  │
│  views/Messages.vue  (私聊) │         │  PrivateMessageController        │
│  views/StudyGroup.vue (群聊)│  REST   │  StudyGroupController            │
│        │                    │ ──────▶ │  PrivateMessageService           │
│  api/im.ts / studyGroup.ts  │  /api   │  StudyGroupService              │
│        │                    │         │  (MyBatis-Plus + MySQL)          │
│  utils/ws.ts  ───────────────────────────▶  /ws/im  (ImWebSocketHandler) │
│                             │  WebSocket│  /ws/group(GroupWebSocketHandler)│
│                             │         │  WebSocketAuthInterceptor (JWT)  │
└─────────────────────────────┘         └──────────────────────────────────┘
```

- **通信双通道**：
  - **REST（HTTPS）**：会话管理、历史消息分页、已读标记、撤回、文件上传。
  - **WebSocket（WS）**：实时收发消息、已读回执广播、撤回广播、输入中状态、未读会话更新。
- **鉴权**：REST 用 `Authorization: Bearer <JWT>`；WebSocket 因浏览器不支持自定义请求头，token 通过握手查询参数 `?token=<JWT>` 传递，由 `WebSocketAuthInterceptor` 解析并写入 `session.attributes["userId"]`。

## 3. 数据模型（Database Schema）

遵循《阿里巴巴 Java 开发手册》：逻辑删除 `deleted`、表名小写非复数、必备 `id/create_time/update_time`、表间逻辑外键（无物理外键/级联）、逻辑外键列建索引。

### 3.1 私聊相关表

#### `private_conversation`（单聊会话）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | 自增 |
| `user_a_id` | BIGINT | 用户 ID（**约定 `user_a_id < user_b_id`**，保证会话唯一） |
| `user_b_id` | BIGINT | 用户 ID（较大一方） |
| `last_message_id` | BIGINT | 最后一条消息 ID（会话预览用） |
| `last_message_time` | DATETIME | 最后消息时间 |
| `create_time` / `update_time` / `deleted` | — | 标准字段 |

索引：`uk_pc_users(user_a_id, user_b_id, deleted)` 唯一；`idx_pc_user_a`、`idx_pc_user_b`。

#### `private_conversation_read`（私聊已读游标）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | 自增 |
| `conversation_id` | BIGINT | 会话 ID（逻辑外键，建索引） |
| `user_id` | BIGINT | 用户 ID（逻辑外键，建索引） |
| `last_read_message_id` | BIGINT | 该用户已读到的最后消息 ID（游标语义） |

索引：`uk_pcr_conv_user(conversation_id, user_id, deleted)` 唯一；`idx_pcr_user(user_id)`。

#### `private_message`（私聊消息）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | 自增 |
| `conversation_id` | BIGINT | 所属会话（逻辑外键，索引） |
| `sender_id` | BIGINT | 发送者（逻辑外键，索引） |
| `message_type` | VARCHAR | `TEXT` / `IMAGE` / `FILE` / `CODE` |
| `content` | TEXT | 文本内容（IMAGE/FILE 时为说明文字，CODE 时为代码） |
| `file_url` | VARCHAR | 文件/图片访问路径（如 `/uploads/yyyy/MM/dd/uuid.ext`） |
| `file_name` | VARCHAR | 原始文件名 |
| `file_size` | BIGINT | 文件大小（字节） |
| `code_language` | VARCHAR | CODE 类型时的语言 |
| `recalled` | INT | `0` 未撤回 / `1` 已撤回（软标记，不物理删除） |

索引：`idx_pm_conv(conversation_id)`、`idx_pm_sender(sender_id)`、`idx_pm_ctime(create_time)`。

### 3.2 群聊相关表

#### `study_group` / `study_group_member`
（学习小组及其成员；成员表含 `last_read_message_id` 字段，作为**群聊已读游标**，与私聊单独建表的设计不同。）

索引：`study_group_member` 有 `uk_sgm_group_user(group_id, user_id, deleted)` 唯一、`idx_sgm_user`、`idx_sgm_role`。

#### `study_group_message`（群聊消息）
| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT PK | 自增 |
| `group_id` | BIGINT | 所属小组（逻辑外键，索引） |
| `sender_id` | BIGINT | 发送者（逻辑外键，索引） |
| `message_type` | VARCHAR | `TEXT` / `IMAGE` / `FILE` / `CODE` |
| `content` / `file_url` / `file_name` / `file_size` / `code_language` | — | 同私聊 |
| `mention_user_ids` | VARCHAR | 被 @ 的用户 ID，逗号分隔 |
| `recalled` | INT | `0/1` 撤回标记 |

索引：`idx_sgm_group(group_id)`、`idx_sgm_sender(sender_id)`、`idx_sgm_type(message_type)`、`idx_sgm_ctime(create_time)`。

## 4. 后端实现

### 4.1 模块划分
- **Entity**：`PrivateMessage` / `PrivateConversation` / `PrivateConversationRead` / `StudyGroupMessage`（均继承 `BaseEntity`）。
- **Mapper**：对应 4 个 `BaseMapper<T>`，无自定义 SQL。
- **Service**：`PrivateMessageService` + `impl`；`StudyGroupService` + `impl`。
- **Controller**：`PrivateMessageController`（`/api/im/private`）、`StudyGroupController`（`/api/study-groups`）。
- **WebSocket**：`ImWebSocketHandler`（`/ws/im`）、`GroupWebSocketHandler`（`/ws/group`）、`WebSocketAuthInterceptor`、`WebSocketConfig`。

### 4.2 关键设计决策

1. **单聊会话唯一性**：`user_a_id < user_b_id` 约定 + `uk_pc_users` 唯一索引，保证任意两人只有一个会话，避免重复会话。
2. **已读游标模型**
   - 私聊：`private_conversation_read` 表保存 `(conversation_id, user_id) → last_read_message_id`。
   - 群聊：`study_group_member.last_read_message_id` 字段（游标在成员表上）。
   - 未读数 = 会话内 `id > 我的游标` 的消息条数。
3. **「已读」语义**：仅对「我发出的消息」有意义。读取历史时，`vo.read = isMine && 对方游标 != null && 我的消息ID <= 对方游标`。
4. **消息撤回**：`recalled` 软标记（=1），不物理删除；前端展示「[撤回的消息]」。仅消息发送者可撤回（后端校验 `sender_id == 当前用户`）。
5. **序列化安全**：WebSocket 发送统一使用 **Spring 托管的 `ObjectMapper`**（已注册 `jackson-datatype-jsr310`），禁止自行 `new ObjectMapper()`（否则 `LocalDateTime` 序列化抛 `InvalidDefinitionException`）。
6. **并发发送安全**：同一 `WebSocketSession` 的 `sendMessage` 必须 `synchronized(session)`，避免 Tomcat 多线程并发写触发 `TEXT_PARTIAL_WRITING` 竞态导致消息丢失。

### 4.3 REST API 清单

#### 私聊 `PrivateMessageController`（`/api/im/private`）
| 方法 | 路径 | 说明 | 返回 |
|---|---|---|---|
| POST | `/conversations?targetUserId=` | 获取/创建与用户的会话 | `PrivateConversationVO` |
| GET | `/conversations` | 我的会话列表 | `List<PrivateConversationVO>` |
| GET | `/conversations/{id}/messages?page=&size=` | 历史消息分页（倒序） | `Page<PrivateMessageVO>` |
| POST | `/messages` | 发送消息（REST 路径，含 WS 广播 `pushToPeer`） | `PrivateMessageVO` |
| POST | `/conversations/{id}/read` | 标记已读 → 返回游标并 `broadcastReadReceipt` | `Void` |
| GET | `/conversations/{id}/unread` | 未读数 | `Integer` |
| DELETE | `/messages/{id}` | 撤回（仅本人）→ `broadcastRecall` | `Void` |

#### 群聊 `StudyGroupController`（`/api/study-groups`）
| 方法 | 路径 | 说明 | 返回 |
|---|---|---|---|
| GET | `/{id}/messages?page=&size=` | 群历史消息分页 | `Page<GroupMessageVO>` |
| POST | `/messages` | 发送消息（**仅持久化，不广播 WS**） | `GroupMessageVO` |
| DELETE | `/messages/{id}` | 撤回（仅本人）→ `broadcastRecall` | `Void` |
| POST | `/{id}/read` | 标记已读（更新成员游标，**不广播**） | `Void` |
| GET | `/{id}/unread` | 未读数 | `Integer` |
| POST | `/upload` (multipart) | 上传图片/文件（**仅群聊有此端点**） | `{fileName, fileUrl, fileSize, fileType}` |

> **上传目录**：`@Value("${app.upload.dir:uploads}")`，按 `yyyy/MM/dd/` 分目录，返回 `fileUrl=/uploads/yyyy/MM/dd/<uuid><ext>`。静态资源由 `WebMvcConfig` 映射 `/uploads` 可访问。

### 4.4 WebSocket 协议

#### 4.4.1 鉴权与连接
- 握手：`GET /ws/im?token=<JWT>` 或 `/ws/group?token=<JWT>`。
- `WebSocketAuthInterceptor.beforeHandshake` 解析 token → 取 `userId` → 写入 `session.attributes["userId"]`；失败关闭连接。
- `WebSocketConfig`：`setAllowedOrigins("*")` 跨源放行（开发环境前端直连后端端口需要）。

#### 4.4.2 私聊帧格式 `/ws/im`

**入站（client → server）**
```jsonc
// 发送消息（前端主路径）
{ "type": "message", "conversationId": 12, "messageType": "TEXT",
  "content": "hello", "fileUrl": null, "fileName": null, "fileSize": null, "codeLanguage": null }
// 标记已读
{ "type": "read", "conversationId": 12 }
// 输入中状态
{ "type": "typing", "conversationId": 12, "isTyping": true }
```

**出站（server → client）**
```jsonc
// 新消息（对方或自己都收到，多端同步）
{ "type": "message", "data": { /*PrivateMessageVO*/ } }
// 会话未读更新（推给对方）
{ "type": "conversation_update", "conversationId": 12, "unreadCount": 3 }
// 已读回执广播（双方都收到）
{ "type": "read_receipt", "conversationId": 12, "userId": 5, "lastReadMessageId": 88 }
// 输入中
{ "type": "typing", "conversationId": 12, "userId": 5, "isTyping": true }
// 撤回广播（双方都收到）
{ "type": "recall", "conversationId": 12, "messageId": 88 }
```

#### 4.4.3 群聊帧格式 `/ws/group`

**入站（client → server）**
```jsonc
{ "type": "join", "groupId": 7 }            // 进入小组房间
{ "type": "leave", "groupId": 7 }           // 离开房间
{ "type": "message", "groupId": 7, "messageType": "TEXT", "content": "hi", ... }
{ "type": "typing", "groupId": 7, "isTyping": true }
```

**出站（server → client）**
```jsonc
{ "type": "message", "data": { /*GroupMessageVO*/ } }      // 广播给房间内所有人
{ "type": "user_joined", "userId": 5, "timestamp": 123 }   // 有人加入
{ "type": "user_left", "userId": 5, "timestamp": 123 }     // 有人离开
{ "type": "mention", "groupId": 7, "messageId": 9, "senderName": "A", "content": "..." } // @提及通知
{ "type": "typing", "userId": 5, "isTyping": true }         // 输入中（已排除自己）
{ "type": "recall", "groupId": 7, "messageId": 9 }         // 撤回广播（全组）
{ "type": "error", "message": "...", "timestamp": 123 }     // 错误
```

## 6. 关键流程时序

### 6.1 私聊发送 + 实时推送
```
用户A 发送 ──WS(type:message)──▶ ImWebSocketHandler.handleMessage
   │  1. privateMessageService.sendMessage() 落库
   │  2. sendToUser(用户B, {type:message, data:VO})
   │  3. sendToUser(用户A, {type:message, data:VO})   // 多端同步
   │  4. sendToUser(用户B, {type:conversation_update, unreadCount})
```
（REST `POST /api/im/private/messages` 也会调 `imWebSocketHandler.pushToPeer` 走同样的广播。）

### 6.2 私聊已读回执
```
用户B 打开会话 ── WS(type:read) ─▶ handleRead
   → privateMessageService.markAsRead() 写游标
   → broadcastReadReceipt(conversationId, B, lastReadId)
   → 用户A 收到 {type:read_receipt} → 其发出且 id<=游标的消息显示「已读」
```

### 6.3 消息撤回
```
用户A 撤回 ── DELETE /api/im/private/messages/{id}
   → recallMessage() 置 recalled=1
   → broadcastRecall(conversationId, messageId)
   → 双方收到 {type:recall} → 该消息渲染为「[撤回的消息]」
```
（群聊同理，`DELETE /api/study-groups/messages/{id}` → `GroupWebSocketHandler.broadcastRecall` 全组广播。）

## 7. 安全设计
- **鉴权**：REST 走 `Authorization` 头；WS 走 `?token=` 查询参数，经 `WebSocketAuthInterceptor` 解析 JWT 取 `userId`。
- **越权防护**：撤回接口后端强制校验 `message.senderId == 当前用户`，否则抛异常。
- **跨域**：`WebSocketConfig.setAllowedOrigins("*")` 对 WS 跨源放行（开发需要）；生产应收窄白名单。
- **XSS**：前端渲染消息 HTML（markdown 分支）须用 DOMPurify 清洗；CODE 类型按纯文本渲染。
