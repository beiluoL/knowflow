## 0. 文档说明与范围

### 0.1 为什么对比对象是「桌面端 vs Web 端」

原始任务是「对比桌面端学习工作台 与 web 端项目中的移动端学习工作台」。经实勘 knowflow 代码库后发现：

- **真正完整的学习工作台**只存在于两处：
  1. `desktopApp/`（Tauri + Vue3 + Fastify/SQLite）—— 由 Web 端迁出后独立演进、功能大幅增强；
  2. `frontend/ + backend/`（Vue3 + Spring Boot）—— Web 端工作台（8 大模块权威实现）。
- 项目里名为「移动端」的两个候选 **均不具备可比的工作台能力**：
  - `mobile/`（Flutter，名为「KnowFlow AI 学习平台移动端」）—— **空壳**，仅有占位卡片、零业务逻辑、无 `/workbench` API、无数据模型；
  - `miniprogram/`（微信小程序「CodeLearn」）—— **独立轻产品**，仅有静态闪卡 + 静态统计 demo，无捕获/笔记/宫殿/故事/回忆模块、无 API 层。

因此「web 端项目中的移动端学习工作台」这一对象在代码库中**不存在**。经与用户确认，调整对比基线为：

> **以 Web 工作台（frontend + backend）为基准，以桌面端（desktopApp）为「功能领先端」，梳理两端差距，并据此制定「Web 端功能照桌面端补齐」的同步开发计划。**

故本对比文档的对象为 **桌面端 vs Web 端**，原需求中的「桌面端与移动端差异明细」在此落地为「桌面端与 Web 端差异明细」。

### 0.2 两端技术栈速览

| 维度 | 桌面端 `desktopApp/` | Web 端 `frontend/ + backend/` |
|---|---|---|
| 前端 | Vue3 + Vite + Pinia + Tailwind | Vue3 + Vite + Pinia + Tailwind |
| 后端 | Node + Fastify + TypeScript（本地优先，SQLite/Drizzle） | Spring Boot 3 + MyBatis-Plus + MySQL/H2 |
| 架构 | Tauri 2 外壳 + 本地侧车，单用户，离线优先 | B/S 多用户，云端，JWT + WebSocket |
| 工作台规模 | 8 核心模块 + 15+ 生产力/增强模块，约 190+ 端点 | 8 核心模块 + 文档/社区/编程/学习路径等平台生态 |

### 1.1 Web 端独有、桌面端缺失的能力

下列能力 Web 端已经具备、而桌面端尚无（补齐计划应**保留 Web 既有生态，不逆转**）：

- **社区 / 学习小组 / 私信**：`CommunityController` / `StudyGroupController` / `PrivateMessageController`
- **编程 AI 闭环**：编程 Agent、代码沙箱、代码题库、闯关 `CodeAgent/CodeChallenge/CodeRun`
- **智能测验 / 智能写作**：`SmartQuiz` / `SmartWriting`
- **学习路径个性化**：`generatePersonalizedPath` 按目标/水平/每日分钟生成路径
- **游戏化成长**：成就、排行榜、学习宠物、经验/精力消耗模型
- **管理后台（B 端）**：`/admin/*` 共 11 个控制器
- **OAuth 第三方登录** + 令牌黑名单
- **知识图谱生态**：力导向知识图谱、多源导入、文档向量化与 RAG 检索

### 1.2 桌面端自身空壳项（两端共同的「待补」方向）

桌面端设置中心内 `SyncSection` / `ShortcutSection` / `NotificationSection` 为 **UI 空壳**（后端未接线），对应其 P1 缺口 F1–F3。Web 端在「通知」上反而略好（`/api/notifications` 已落地），但在「多设备云同步」「系统级快捷键」上同样缺失。此部分在开发计划中作为横切项处理。

## 2. 桌面端与 Web 端差异明细

### 2.1 工作台核心模块差异（重点）

**① 间隔复习（模块 3）—— Web 落后**
- 桌面端：`wb_review_card` + `wb_review_log` 双套并存——旧卡组（SM-2）+ 跨源系统（覆盖 `note` 与 `loci` 的统一复习队列，含热力图、遗忘曲线、助记口诀采纳）。
- Web 端：仅单套 SM-2（`WorkbenchController` 的 `/reviews`、`/reviews/draw`、`/reviews/{id}/grade`、遗忘曲线 VO）。
- 差距：缺**跨源统一复习队列**与可选的 **FSRS 类第二算法**对比调度。

**② 记忆宫殿（模块 4）—— Web 落后**
- 桌面端：记忆桩支持 **AI 自动生成**（内容挂载 + 桩位布置）、导览漫游（TourView）、位点自带 SRS 字段并可进入复习。
- Web 端：记忆桩需**手动创建 + 画布拖拽坐标**（`WorkbenchPalaceEdit.vue`），无 AI 辅助生成。
- 差距：缺 AI 生成桩位、导览漫游、位点级 SRS。

**③ 主动回忆（模块 5）—— Web 落后**
- 桌面端：`scoreRecall()` 使用 **LLM 语义相似度**评分 + 进步率 + 改进建议。
- Web 端：提交轮次后**文本字符串比对/相似度**自动计分，无语义层。
- 差距：缺语义化评分（需 LLM 接口与评分服务）。

**④ 收集箱（模块 1）—— Web 偏弱**
- 桌面端：去重检测（inboxDedupeService）、网页剪藏（inboxClipService）、语音/附件上传（inboxUploadService）、多目标沉淀（转笔记/宫殿/故事）。
- Web 端：基础 CRUD + 状态流转 + 标星，无上述增强。
- 差距：捕获增强链路整体缺失。

**⑤ 笔记（模块 2）—— Web 持平、局部偏弱**
- Web 端三栏（线索/笔记/总结）字段与桌面对齐（`cueColumn`/`noteColumn`/`summaryColumn`/`mastery`）。
- 差距：缺双链反链、标签云、单篇 Markdown/PDF 导出（桌面同样未做单篇导出，属共同缺口 F4）。

**⑥ 导入导出（模块 8）—— Web 落后（单向）**
- 现状：Web `GET /workbench/export` 导出 JSON 供桌面消费；桌面 `POST /api/workbench/import` 导入。**逆向通道（桌面→Web 整库导入）不存在**。
- 差距：缺 Web 端消费桌面整库的导入层与格式兼容。

### 2.2 生产力增强模块差异

| 模块 | 桌面端 | Web 端 | 关键差距点 |
|---|---|---|---|
| 思维导图 | ✅（CRUD + AI 生成，JSON 存储） | ❌ | 仅有知识图谱，无中心节点放射编辑器 |
| 绘图/流程图 | ✅（X6 画布、撤销重做、draw.io 导入、PDF 导出、AI 生成） | 🟡（文档内 Mermaid 渲染） | 无独立流程图编辑器 |
| 任务清单 | ✅（Things3：五智能列表、子任务、清单/领域/项目层级） | 🟡（成长任务中心：每日/周/月 + 经验奖励，无 `parentId`/层级） | 缺层级任务与智能列表 |
| 四象限 | ✅（2×2 拖拽 `wb_quadrant_task`） | ❌ | 完全缺失 |
| 日历事件 | ✅（月/周/日三视图、范围查询） | ❌ | 完全缺失（仅有打卡热力图） |
| 整库备份 | ✅（整库 zip + 定时调度 + 列表/打开） | ❌ | 仅模块级导出，无整库快照/恢复 |
| 命令面板 | ✅（⌘K 可操作命令列表：新建/跳转/动作） | 🟡（⌘K 仅跳转搜索页） | 非命令面板，无可执行动作 |
| 新手引导 | ✅（onboarding 向导 + 标记位） | ❌（仅导入向导，无首次登录 tour） | 缺独立 onboarding |
| 每日学习日报 | ✅（AI 聚合 + 薄弱点→闪卡） | ❌ | 仅有周报/学习报告 |
| 模拟面试 | ✅（Whisper STT + LLM + TTS 多轮 + 题库汇入） | 🟡（有编程题库/答题，无面试会话） | 缺模拟面试流程与通用 QA Bank |

### 2.3 持平与 Web 领先项（不纳入补齐范围）

- **持平**：康奈尔笔记、费曼故事、看板/总览、文档库双链、习惯打卡、番茄钟、AI 助手/RAG、社区/编程/路径/游戏化/管理后台/OAuth（Web 独有）。
- **Web 领先**：通知中心（`/api/notifications` 已落地，桌面为壳）、平台生态广度（社区/编程/路径/游戏化）。
- 结论：补齐计划**只针对 Web 落后于桌面的项**，Web 既有生态与领先项应保留并可能被桌面反向吸收（不在本文范围）。

## 3. 差距评估

### 3.1 量化汇总

| 维度 | 数量 | 说明 |
|---|---|---|
| 🟢 完全持平 | 9 | 笔记、费曼、看板、文档库、习惯、番茄钟、AI助手、+ Web 独有 8 类不计 |
| **Web 落后（同功能弱于桌面）** | **5** | 间隔复习(双SRS)、记忆宫殿(AI桩)、主动回忆(语义评分)、收集箱(增强)、任务清单(层级) |
| **Web 缺失（桌面有、Web 无）** | **7** | 思维导图、绘图编辑器、四象限、日历事件、整库备份、每日日报、模拟面试 |
| Web 偏弱（局部缺能力） | 3 | 命令面板(仅跳转)、新手引导(缺失)、导入导出(单向) |
| 双方偏弱 | 2 | 周/月/年仪表盘、多设备云同步 |

> 计入核心+增强共 23 项：持平 9、Web 落后 5、Web 缺失 7、Web 偏弱 3、双方弱 2（合计 23，含重叠口径）。

### 3.2 优先级矩阵（影响 × 工作量）

| 优先级 | 模块 | 影响（用户感知） | 工作量 | 建议阶段 |
|---|---|---|---|---|
| P0 | 命令面板 + 新手引导 | 高（首屏体验） | 低 | 阶段 1 |
| P0 | 双向迁移 + 整库备份 | 高（数据安全/跨端） | 中 | 阶段 2/4 |
| P1 | 双 SRS / AI 记忆桩 / 语义评分 | 高（学习效率核心） | 中-高 | 阶段 2 |
| P1 | 思维导图 / 绘图 / 四象限 / 日历 | 中-高（生产力闭环） | 高 | 阶段 3 |
| P1 | Things3 任务清单 | 中 | 中 | 阶段 3 |
| P2 | 每日学习日报 / 月年仪表盘 | 中（复盘） | 中 | 阶段 4 |
| P2 | 模拟面试 + QA Bank | 中 | 中-高 | 阶段 4 |
| P3 | 全局搜索语义增强 / 设置三分区接线 | 低-中 | 低-中 | 阶段 5 |

### 3.3 关键结论

1. **工作台「骨架」两端已对齐**：8 大核心模块 Web 端全部具备且基本可用，差距主要在**算法深度与 AI 增强**（双 SRS、AI 记忆桩、语义评分）。
2. **生产力闭环是最大缺口**：思维导图、绘图、四象限、日历、整库备份、每日日报、模拟面试共 7 项 Web 完全缺失，构成「个人效率工作台」与桌面的本质差距。
3. **迁移目前单向**：Web→桌面 可导出，逆向不可；需补 Web 端导入层以真正「同步」。
4. **Web 有桌面没有的平台生态**（社区/编程/路径/游戏化），补齐时务必**保留**，避免「为对齐而降级」。
5. **横切能力（云同步/快捷键/通知）两端都弱**，建议作为专项在收尾阶段统一接线。
