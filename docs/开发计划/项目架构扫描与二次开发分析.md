## 1. 当前项目架构

### 1.1 整体技术栈

| 层 | 技术选型 |
|----|---------|
| 前端 | Vue 3 `<script setup lang="ts">` + Composition API + Pinia + Vue Router + Vite + Tailwind CSS |
| 后端 | Spring Boot 3.x + MyBatis-Plus + JWT + MySQL / H2（双方言 schema） |
| AI | OpenAI Compatible API 抽象（ModelAdapter 工厂），支持 11 云端提供商 + 4 类本地推理 |
| RAG | Apache Tika 解析 + 段落分块 + Embedding 向量化 + 余弦相似度检索 + LLM 生成 |
| 桌面端 | Tauri（Rust + Vue）独立项目 desktopApp/，与 Web 端共享工作台记忆模块 |
| 文档 | 双目录：doc/（产品/技术方案/部署）+ docs/（开发计划/差异对比） |

### 1.2 后端分层结构（com.knowflow 包）

```
com.knowflow
├── ai/                    # AI 适配层（Provider 抽象）
│   ├── ModelAdapter.java        # 统一接口：chat / streamChat / chatMulti / streamMulti
│   ├── ModelAdapterFactory.java # 按 protocol 选择 Adapter
│   ├── OpenAiAdapter.java       # OpenAI Compatible（DeepSeek/Qwen/SiliconFlow 等）
│   ├── AnthropicAdapter.java    # Claude 系
│   ├── QianfanAdapter.java      # 文心一言（双密钥）
│   └── SseClient.java           # SSE 流式连接管理
├── agent/                 # AI Agent 基础设施
│   ├── tool/                    # AgentTool / ToolResult 工具协议
│   └── ToolContext.java         # 工具执行上下文
├── common/                # 通用：Result / PageQuery / PageResult / SecurityUtils
├── config/                # AiConfig / AiProviderRegistry / CorsConfig / OAuthConfig / WebMvcConfig
├── controller/            # REST Controller（按业务域划分，约 30+ 个）
├── dto/                   # 请求 DTO（约 45 个）
├── entity/                # 实体类（47 个，含 Phase 1 LearningEvent，均 extends BaseEntity，@TableName 映射）
├── mapper/                # MyBatis-Plus Mapper（BaseMapper 子类）
├── service/               # Service 接口（10+ 个）
│   └── impl/                    # ServiceImpl 实现
├── util/ + utils/         # AnkiApkgParser / LunarCalendar / UploadHelper / JwtUtils
└── vo/                    # 视图 VO（约 80 个）
```

### 1.3 前端结构（frontend/src/）

```
src/
├── api/                   # 统一请求封装（request.ts + 按域分模块 20+ 个）
├── components/ui/          # 全局 UI 组件（25 个：Button/Icon/Card/Select/CommandPalette 等）
├── composables/            # 组合式函数（useCommandRegistry/useCommandPalette/useStudyReminder 等）
├── router/index.ts         # 65 条路由（C 端 + B 端管理后台 + 无布局页）
├── stores/                 # Pinia（auth / knowledge / pomodoro 等）
├── style.css               # Design System（--kb-* 令牌 + 全局 .kb-* 类）
├── views/                  # 页面视图（60+ 个，按功能域分目录）
├── App.vue                 # 根布局：按 meta.layout 挂载 CLayout / AppShell
└── main.ts                 # 入口：Pinia + Router + 全局样式
```

### 1.4 布局约定

- `meta.layout = 'c'` → C 端：固定顶部导航 + 全屏内容（无侧边栏）
- `meta.layout = 'b'` → B 端：左侧边栏 + 顶部栏 + 可滚动内容（管理后台）
- `meta.layout = 'none'` → 无布局壳（登录/404/沉浸式页面）

## 5. 数据模型关系

### 5.1 学习行为数据流（当前散落）

```
用户学习行为 → 散落在 12 张表（无统一事件层）
├── 阅读文档      → doc_read_progress
├── 完成章节      → learning_user_chapter（complete_time / video_progress）
├── 答题          → quiz_answer_record（is_correct / score / time_cost）
├── 代码提交      → code_submit_record（pass_count / passed）
├── 闯关          → code_challenge_level_record（stars / attempts）
├── 错题          → learning_mistake（mastered / review_count）
├── 闪卡复习      → learning_flashcard.next_review_time（SM-2 由 reviewFlashcard 调度）
├── 工作台复习    → wb_review_card + wb_review_log（SM-2 完整）
├── 主动回忆      → wb_recall_session（round1/2/3_score）
├── 每日打卡      → user_check_in（continuous_days）
├── 习惯打卡      → habit_checkin（count）
├── 专注会话      → focus_session（completed_pomodoros / quality_rating）
└── AI 对话       → chat_message
```

### 5.2 核心实体关系

```
sys_user（用户）
├── 1:N → learning_user_path → learning_path → learning_chapter（DAG 前置依赖）
│                                    └── learning_flashcard（SM-2 next_review_time）
├── 1:N → quiz_answer_record → quiz_question（5 题型，category_id/doc_id 关联知识库）
├── 1:N → code_submit_record → code_question
├── 1:N → code_challenge_record → code_challenge → code_challenge_level
│              └── code_challenge_level_record（stars/attempts）
├── 1:N → learning_mistake（source: quiz/code）
├── 1:N → learning_certificate → learning_path
├── 1:N → wb_capture → wb_note（mastery 自评）→ wb_review_card（SM-2）
│         │                └── wb_recall_session（三轮默写）
│         └── wb_story（费曼，gap_note 知识漏洞）
├── 1:N → doc_document → doc_chunk（embedding 向量）
│         └── kg_entity → kg_relation（AI 抽取知识图谱）
├── 1:N → agent_session → agent_message / agent_tool_call
├── 1:N → learning_plan（今日计划，time_blocks JSON）
├── 1:N → user_check_in / habit_checkin / focus_session
├── 1:N → community_post / community_comment
└── 1:1 → sys_user_ai_config（is_active=1 标记当前唯一配置）
```

## 6. AI 架构

### 6.1 Provider 抽象（已实现，可扩展）

```
AiService（业务接口）
├── chat / complete           ← 非流式
├── streamChat（3 重载）      ← SSE 流式
├── chatMulti / streamMulti   ← Agent 多轮 + 工具调用
├── gradeEssay                ← 简答题评分
├── chatWithImages            ← 多模态
├── healthCheck              ← 模型可用性检测
└── supportsTools             ← Function Calling 能力判断
        │
        ▼
AiServiceImpl
├── resolveEffectiveConfig    ← 用户 Key 优先 → 全局回退
├── callModel                 ← 统一模型调用入口
        │
        ▼
ModelAdapterFactory（按 protocol 选择 Adapter）
├── OpenAiAdapter    ← OpenAI Compatible（DeepSeek/Qwen/SiliconFlow/GLM/Kimi/Doubao/Hunyuan/Wenxin/Custom）
├── AnthropicAdapter ← Claude 系
└── QianfanAdapter    ← 文心一言（双密钥）

AiProviderRegistry：11 云端提供商 + 4 类本地（Ollama/vLLM/LocalAI/Custom）
```

### 6.2 用户自配 Key 机制

- `sys_user_ai_config` 表：每用户可有多条配置（编程 Agent 场景），通用 Chat 用 `is_active=1` 标记唯一
- `resolveEffectiveConfig(userId)`：优先读 UserAiConfig 的 apiKey/baseUrl/model，回退全局 application.yml
- 新增 AI 功能天然支持用户级配置，无需额外开发

### 6.3 RAG 链路（已完整实现）

```
文档上传 → DocService（Apache Tika 解析 PDF/DOC/DOCX/PPT/TXT/MD）
        → DocChunkService.indexDocument
            ├── 段落分块（chunk_index）
            ├── EmbeddingService.embedBatch（向量化）
            └── doc_chunk 表（embedding 逗号分隔浮点数组）
检索 → DocChunkService.searchSimilar
            ├── 查询文本 embedding
            ├── 加载带 embedding 的分块
            ├── 余弦相似度计算 + 排序
            └── 文档级召回（按最高分块得分聚合）
生成 → AiService.chat(userMessage, contextDocs) ← 基于检索上下文
```

### 6.4 Agent 基础设施（已完备，Phase 3 可直接复用）

## 7. 学习闭环现状

### 7.1 闭环环节盘点

```
目标 ──────────────────── ✓ ai_personalized_path（AI 生成个性化路径）
  ↓
学习路径 ──────────────── ✓ learning_path/chapter + DAG 依赖
  ↓
知识学习 ──────────────── ✓ doc_document/chunk + RAG 检索
  ↓
AI 教学 ───────────────── ✓ ChatService + 概念图解（ai_concept_diagram）
  ↓
RAG ───────────────────── ✓ DocChunkService 完整链路
  ↓
练习（Quiz）───────────── ✓ quiz_question + 答题判分 + 错题归集
  ↓
代码实战 ──────────────── ✓ code_question + 沙箱执行 + AI 评估
  ↓
AI 评估 ───────────────── ✓ gradeEssay + codeAssess
  ↓
错题 ──────────────────── ✓ learning_mistake（source: quiz/code）
  ↓
主动回忆 ──────────────── ✓ wb_recall_session（三轮默写）  ← 已实现！
  ↓
SRS 复习 ──────────────── ◐ wb_review_card（SM-2）仅覆盖工作台卡片，未覆盖 flashcard/mistake
  ↓
掌握度 ────────────────── ✗ 无知识点级掌握度表（仅 getCategoryMastery 分类级）
  ↓
知识图谱 ──────────────── ✓ kg_entity/relation，但无掌握度着色
  ↓
发现薄弱点 ────────────── ◐ getCategoryMastery（<60% weak），但未反馈到路径
  ↓
AI 自动调整学习路径 ──── ✗ learning_path 静态，无自适应
  ↓
考试 ──────────────────── ✗ 无独立考试模块（Quiz 练习 ≠ 考试）
  ↓
模拟面试 ──────────────── ✗ 无 mock_interview
  ↓
作品 ──────────────────── ✗ 无 portfolio
  ↓
证书 ──────────────────── ✓ learning_certificate（路径完成自动颁发）
  ↓
简历 ──────────────────── ✗ 无 resume
```

### 7.2 闭环断裂总结

**已打通：** 目标→路径→学习→RAG→练习→代码→错题→主动回忆→复习→证书（前半段 + 末端证书）

**断裂 3 处：**
1. **掌握度断层**：复习完成后，无法生成知识点级掌握度分数 → 图谱无着色 → 无法发现薄弱点
2. **自适应断层**：发现薄弱点后，无法自动调整学习路径（增加复习/回退前置/跳过基础/增加代码练习）
3. **出口断层**：证书之后无模拟面试/作品集/简历，无法证明"真正掌握"

**割裂数据源：** 学习行为散落 12 张表，无统一事件层，AI Coach 无法全局感知
