HashMap 底层原理与源码解析

#HashMap #源码 #数据结构

HashMap 是 Java 开发中最常用的集合类之一，它基于哈希表实现，提供了高效的键值对存储和查找能力。在日常开发中，理解 HashMap 的底层实现原理，对于编写高性能代码和排查问题都有着重要的意义。

1. HashMap 数据结构

在 JDK 1.8 及之后的版本中，HashMap 采用了「数组 + 链表 + 红黑树」的复合数据结构。当链表长度超过阈值（默认为 8）且数组长度达到 64 时，链表会转换为红黑树，以提升查找效率。

这种设计兼顾了哈希冲突较少时的快速访问和冲突较多时的稳定性能。数组中的每个位置被称为一个「桶」（bucket），每个桶初始时为空，当发生哈希冲突时则以链表形式存储多个元素。

public class HashMap<K,V> extends AbstractMap<K,V>

    static final int DEFAULT_INITIAL_CAPACITY = 1 << 4;

    // 链表转红黑树的阈值
    static final int TREEIFY_THRESHOLD = 8;

    // 红黑树转链表的阈值
    static final int UNTREEIFY_THRESHOLD = 6;

2. put 方法流程

当我们调用 map.put(key, value) 时，HashMap 内部会执行以下关键步骤来完成数据的插入操作。

核心要点

HashMap 通过 hash(key) & (n - 1) 计算数组下标，其中 n 必须是 2 的幂次方，这样可以利用位运算替代取模运算，提升计算效率。

  1. 首先计算 key 的 hash 值，并经过扰动函数（high-bit 参与运算）减少哈希碰撞。
  2. 通过 hash & (n - 1) 定位到数组下标位置。
  3. 如果该位置为空，直接创建新节点插入；如果非空，遍历链表查找是否已存在相同 key。
  4. 找到相同 key 则覆盖旧值并返回；未找到则在链表尾部追加新节点。
  5. 插入后判断元素总数是否超过阈值（容量 x 负载因子），超过则触发扩容操作。
HashMap put 流程图

扩容机制是 HashMap 性能优化中的核心环节。当元素数量达到阈值时，HashMap 会创建一个容量为原来两倍的新数组，并将所有元素重新哈希分配到新的桶中。这个过程称为「rehash」。

在 JDK 1.8 中，rehash 过程做了优化：元素在新数组中的位置只有两种可能——原位置或原位置加旧数组长度。这大大减少了 rehash 时的计算量，提升了扩容效率。

理解这些底层原理后，我们就能更好地回答面试中关于 HashMap 的常见问题，也能在实际开发中做出更合理的技术选型和性能调优。
